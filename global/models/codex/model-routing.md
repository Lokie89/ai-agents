# 모델 라우팅

이 문서는 Codex에서 작업 난이도에 맞춰 실제 모델과 추론 강도를 선택하는 기준입니다. 제품과 계정에 따라 사용 가능한 모델이 달라질 수 있으므로 존재하지 않는 추상 별칭을 런타임 설정처럼 사용하지 않습니다.

## 기본 원칙

- 모델을 고정할 필요가 없으면 현재 세션이나 부모 에이전트의 설정을 상속한다.
- 직접 지정할 때는 현재 환경에서 지원하는 실제 모델 ID와 `model_reasoning_effort`를 사용한다.
- 모델 이름보다 작업의 모호성, 영향 범위, 검증 난이도, 비용과 속도를 함께 고려한다.
- 지원 모델과 추론 강도는 바뀔 수 있으므로 설정을 추가하거나 변경하기 전에 현재 Codex 문서와 환경의 가용성을 확인한다.
- 고위험 작업은 높은 추론 강도만으로 안전해지지 않는다. 승인, 테스트, 독립 검토를 별도로 적용한다.

## 작업 난이도 등급

아래 등급은 판단을 돕는 문서 용어이며 Codex의 모델 별칭이 아니다.

| 등급 | 대표 작업 | 권장 방향 |
| --- | --- | --- |
| 단순 | 파일 탐색, 구조 요약, 반복 정리 | 빠른 모델 또는 낮은 추론 강도 |
| 일반 | 범위가 명확한 구현, 문서 수정 | 기본 모델과 중간 추론 강도 |
| 복잡 | 설계, 도메인 정책, 복잡한 디버깅과 리뷰 | 성능이 높은 모델과 높은 추론 강도 |
| 고위험 | 보안, 권한, 개인정보, 결제, 데이터 삭제·마이그레이션 | 지원되는 높은 추론 강도, 사람 승인, 독립 검토 |

다음 조건이 늘어날수록 더 강한 모델이나 높은 추론 강도를 고려한다.

- 요구사항이나 도메인 정책이 모호하다.
- 여러 모듈과 상태 전이에 영향을 준다.
- 실패 경로, 경계 조건, 회귀 가능성 판단이 어렵다.
- 테스트 전략이나 마이그레이션 전략부터 설계해야 한다.
- 보안, 개인정보, 재무, 법무, 의료 또는 운영 장애 위험이 있다.

작업이 명확한 읽기·검색·반복 처리로 분리되면 더 빠른 모델이나 낮은 추론 강도를 사용할 수 있다. 선택이 애매하면 현재 설정을 유지하고, 모델 변경 자체보다 컨텍스트와 완료 기준을 명확히 한다.

## 역할별 기준

| 역할 | 기본 추론 방향 | 기준 |
| --- | --- | --- |
| `planner` | 높음 | 범위, 정책, 사이드이펙트, 검증 전략 분석 |
| `domain` | 높음 | 도메인 정책 질의와 모델링 판단 |
| `implementer` | 중간 | 범위가 확정된 변경 구현 |
| `reviewer` | 높음 | 버그, 회귀, 테스트 갭, 유지보수성 검토 |
| `security` | 지원되는 높은 수준 | 보안, 권한, 데이터 노출 위험 분석 |
| `explorer` | 낮음~중간 | 읽기 중심 탐색과 후보 위치 확인 |
| `documenter` | 중간 | 문서, 기록, 템플릿 작성 |

역할 기본값보다 실제 작업 위험이 우선한다. 예를 들어 구현 역할이라도 인증이나 데이터 마이그레이션을 다루면 추론 강도를 높이고 별도 검토를 둔다.

## Codex 설정 방식

저장소 기본값은 신뢰된 프로젝트의 `.codex/config.toml`, 개인 기본값은 `~/.codex/config.toml`에 둔다. 일회성 선택은 현재 세션이나 실행 옵션으로 제한한다.

커스텀 에이전트는 YAML frontmatter가 아니라 `.codex/agents/<name>.toml`에 정의한다. 기본 필드는 다음과 같다.

```toml
name = "reviewer"
description = "Correctness, regression, and test-gap reviewer."
model = "<available-model-id>"
model_reasoning_effort = "high"
sandbox_mode = "read-only"
developer_instructions = """
Review the requested diff and report concrete findings first.
"""
```

- `name`, `description`, `developer_instructions`는 커스텀 에이전트의 핵심 필드다.
- `model`과 `model_reasoning_effort`를 생략하면 명시적 spawn 값, `[agents]` 기본값, 부모 설정 순으로 상속된다.
- 지원되는 추론 강도는 모델마다 다를 수 있으므로 값을 고정하기 전에 확인한다.
- 탐색과 리뷰 에이전트는 가능한 경우 `sandbox_mode = "read-only"`로 제한한다.
- 전역 서브에이전트 기본값과 동시 실행 한도는 `.codex/config.toml`의 `[agents]`에서 관리한다.

## 멀티 에이전트 선택

- 사용자가 위임이나 병렬 에이전트 작업을 요청했거나 적용 중인 지침이 요구할 때만 서브에이전트를 사용한다.
- 코드 탐색, 테스트, 로그 분석, 독립 리뷰처럼 경계가 분명한 읽기 중심 작업을 우선 위임한다.
- 더 나은 의견 형성이 목표인 작업은 공통 하네스의 `global/harness/deliberation.md`를 따라 Orchestrator가 독립 의견, 비판, 수정, 합성, 검증 라운드를 통제한다.
- 숙의형 작업은 단순 다수결을 사용하지 않고 근거 품질, 정책 적합성, 반대 근거, 남은 리스크를 기준으로 판단한다.
- 같은 파일을 동시에 수정하는 write-heavy 병렬 작업은 충돌과 조정 비용이 크므로 피한다.
- 병렬 쓰기가 꼭 필요하면 작업 파일을 겹치지 않게 나누거나 별도 worktree를 사용한다.
- 위임 프롬프트에는 범위, 이미 확인한 사실, 기대 산출물, 쓰기 허용 여부를 포함한다.

## 검증

- 현재 환경에서 모델 ID와 `model_reasoning_effort`가 지원되는지 확인한다.
- 커스텀 에이전트 파일이 TOML 문법과 Codex 설정 스키마를 따르는지 확인한다.
- 모델이나 추론 강도를 고정한 이유가 비용, 속도 또는 재현성 측면에서 설명 가능한지 확인한다.
- 고위험 작업에 승인과 독립 검토가 모델 선택과 별도로 포함됐는지 확인한다.
